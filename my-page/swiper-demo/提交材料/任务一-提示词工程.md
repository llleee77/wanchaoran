## 一、第 1 轮提示词（故意说得含糊）

> 用 Swiper 11 帮我写一段初始化代码，容器 id 是 `mySwi4`。要求：无缝循环、自动播放、有分页器，初始效果是立方体。

**为什么这一版一定会翻车**：四条需求里有三条只给了"形容词"，没给"参数"。形容词到参数之间，全靠 AI 猜。

### AI 第 1 轮回答（示例）

```js
new Swiper('#mySwi4', {
  loop: true,
  autoplay: { delay: 3000, disableOnInteraction: true },  // 抄的旧版本文档
  pagination: { el: '.swiper-pagination' },               // 没有 clickable
  effect: 'cube'
});
```

看着挺像那么回事。粘进页面逐条验：

| 需求 | 粘贴后看到的 | 判定 |
|---|---|---|
| ① 无缝循环 | 第 6 张之后回到第 1 张，没有空白帧 | ✅ |
| ② 3.2 秒自动翻页 | 能自动翻，但**约 3 秒**就切一张，不是 3.2 秒 | ❌ 数值错 |
| ② 手动操作后不停止 | 手指拖一次，**自动播放直接停了** | ❌ 关键缺陷 |
| ③ 圆点分页器可点击 | 圆点显示正常，**点它没反应** | ❌ |

## 二、第 2 轮提示词（把形容词翻译成参数）

> 在你上一版基础上，按下面四条精确改，每一条都要对应到具体参数，不要省略、不要只给 diff：
>
> 1. `loop` 保持 `true`；
> 2. `autoplay` 必须是对象写法：`{ delay: 3200, disableOnInteraction: false }`。`delay` 必须正好 3200（要 3.2 秒），`disableOnInteraction` 必须 `false`——因为需求是"手动拖动之后自动播放不能停"；
> 3. `pagination` 里 `el` 改成 `'#pager'`，并且加 `clickable: true`，否则圆点点了没反应；
> 4. `effect: 'cube'` 作为初始效果，并补上 `cubeEffect: { shadow: true, slideShadows: true }`。
>
> 只用 Swiper 11 的写法，**不要**用 `autoplay: 3000` 这种 v6 以前的简写。

### AI 第 2 轮回答 → 落地到本项目

```js
new Swiper('#mySwi4', {
  loop: true,                                  // ① 无缝循环
  effect: 'cube',                              // ④ 初始立方体
  cubeEffect: { shadow: true, slideShadows: true },
  autoplay: {
    delay: 3200,                               // ② 3.2 秒
    disableOnInteraction: false,               //    手动操作后不停止
    pauseOnMouseEnter: false                   //    鼠标悬停也不停（我额外加的）
  },
  pagination: {
    el: '#pager',
    clickable: true                            // ③ 圆点可点击
  }
});
```

| 需求 | 验证动作 | 结论 |
|---|---|---|
| ① 无缝循环 | 一直点下一张，第 6 张后回第 1 张 | ✅ 无空白、无跳帧 |
| ② 3.2 秒 | 掐表 / 看 Network 无关，直接数秒 | ✅ 稳定 3.2s |
| ② 手动后不停 | 拖一次，松手，等 3.2s | ✅ 自己又翻过去了 |
| ③ 圆点可点击 | 点第 5 个圆点 | ✅ 直接跳到第 5 张 |
| ④ 初始 cube | 刷新页面 | ✅ 首屏即立方体 |

## 三、答辩答案（老师会抽这三问）

**Q1：你的第一版提示词漏掉了哪个需求？**

漏了三条，而且是同一种漏法——**我只给了形容词，没给判据**：

1. 只写"自动播放"，没写"3.2 秒"，所以 AI 自己选了 3000ms；
2. 只写"自动播放"，没写"手动操作后不能停"，AI 直接从旧版本文档里抄了 `disableOnInteraction: true`，拖一下就停；
3. 只写"有分页器"，没写"能点"，AI 就只给了 `el`，没给 `clickable`。

**Q2：你是怎么在第二轮里"说清楚"的？**

不再描述感受，改成**点名参数 + 说明因果**。比如不说"要能一直自动播"，而是写"`disableOnInteraction: false`，因为需求是手动拖动后自动播放不能停"。参数名是 AI 唯一不会误解的语言；顺带把每个参数为什么这么设也写进去，AI 就没法再"合理发挥"。

**Q3：AI 第一次给的代码错在哪？**

三处，而且都是"不报错但行为不对"的那种错，最难查：

- `delay: 3000` —— 差 200ms，肉眼几乎看不出来，但对不上需求；
- `disableOnInteraction` 被写死成 `true` —— 表现是"手动一拖就再也不自动了"，这是最坑的一处，因为控制台一片安静；
- `pagination` 缺 `clickable` —— 默认 `false`，圆点只是个装饰。

**一句话总结**：AI 不会替你判断"需求有没有被满足"，它只会把你说出口的部分实现掉。**说漏的，就是它会漏的。**

## 四、一个容易说错、但说出来很加分的细节

**Swiper 11 里 `disableOnInteraction` 的默认值是 `false`**（v6–v8 时代才是 `true`）。
所以上面第一版翻车，不是"默认值坑了我"，而是**AI 照抄了旧版本文档，把它显式写成了 `true`**。

这个结论我拿 [对照实验页](../debug/index.html) 验证过：两套配置并排跑，同一个"用户主动切换"动作下去，
A 组（`true`）的 `autoplay.running` 变 `false`，B 组（`false`）仍然是 `true`。

> 答辩时被追问"你怎么确定默认值变了"，就答：我在 11.1.14 的 bundle 里查到
> `extendParams({ autoplay: { delay: 3e3, disableOnInteraction: !1 ... } })`，`!1` 就是 `false`。
